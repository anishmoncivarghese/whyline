# M0.2 Adapter Feasibility Review

**Status:** In progress  
**Decision:** **Adjust and repeat live probes after environment issues are resolved.**

## Environment

| Adapter | Version | Static discovery | Live result |
|---|---|---|---|
| Claude Code | 2.1.173 | Pass | Structured authentication failure; no model turn |
| Codex CLI | 0.146.0-alpha.9.2 | Pass | Successful read-only probe and two successful workspace-write fixture runs |

## Confirmed capabilities

- Both official binaries expose non-interactive invocation.
- Both expose schema-constrained final output mechanisms.
- Claude JSON results contain a session ID, cost, and token-usage structure even on the authentication failure path.
- Codex `--json` emits lifecycle events including `thread.started`, `turn.started`, and structured errors.
- Codex exposes an ephemeral mode and read-only sandbox.
- Codex completed a read-only probe with exit code 0 and exact output, then solved two isolated synthetic tasks with all tests passing.
- Neither probe used a permission-bypass flag or inspected credential storage.

## Live-probe failures

### Claude Code

The process returned exit code 1 with a structured result reporting `Not logged in`. It reported zero tokens and zero cost. This proves the invocation and error-parsing path, not successful model execution or summarisation.

### Codex CLI — first attempt

The workspace-sandboxed run could not write its user-scoped state database. After approved normal execution, the runtime started but remote plugin/model requests and sampling repeatedly timed out. It was interrupted after bounded observation and exited. This proves startup and partial event parsing, not a successful model response.

The alpha CLI also attempted plugin-catalog, analytics, shell-snapshot, certificate, and MCP startup work before completing a minimal read-only prompt. Adapter startup policy and timeouts must account for this behavior; where supported, production invocation should disable unrelated integrations explicitly rather than relying on ambient user configuration.

### Codex CLI — clean-configuration retry

With `--ignore-user-config`, the read-only probe completed in 11.6 seconds and reported structured usage. Two disposable task runs also completed successfully. However, reported input usage was very high: 117,706 tokens for the cold cache task and 153,822 for the human-brief webhook task, mostly cached input. This is an adapter/product-cost finding and requires separating fixed harness context from task context before evaluating the PRD's 40% reduction target.

## Required next actions

1. Authenticate Claude Code through its official user flow outside the adapter, then repeat the live probe.
2. Add a Codex JSON Schema handoff probe after the pilot timing harness is corrected.
3. Separate fixed system/cached context from task-specific usage in analysis.
4. Capture full stdout/stderr to an ignored local results directory with redaction; do not commit raw session output.
5. Test cancellation with a deliberately long but harmless prompt under a fixed timeout.

## Decision

**Adjust.** The adapter abstraction remains plausible, but the PRD exit criterion of two proven non-interactive adapters is not met. Phase 1 remains blocked.
