# whyline-relay 0.2.1 and the combined install

Status: planned, not started. Written 2026-09-21 after the 0.2.0 release.

## What we are solving

1. A user who asks an AI to draft a plan has no way to give it the plan format (`plan-format`).
2. Setup problems show up mid-run: whyline not initialised, an agent logged out, a missing permissions file (`doctor` and a preflight on `start`).
3. Two installs and two init commands. The wish: install once, and let `whyline init` offer the automated relay, with a way to add or remove it later.

## What we measured before designing (2026-09-21)

- **A dependency's command is not put on PATH.** `uv tool install whyline --with whyline-relay` exposes only `whyline` and `whyline-hook`. `whyline-relay` appears only with `--with-executables-from whyline-relay`. But the whyline environment can import `whyline_relay`. So the combined install must run the relay **in-process** as `whyline relay <command>`, and cannot assume a `whyline-relay` command exists.
- **The relay's hints hard-code `whyline-relay <command>`.** Under `whyline relay` they would be wrong, so the relay must print hints using the name it was called by (RELAY-25).
- **Login status is reliable.** Logged out, `codex login status` prints `Not logged in` and exits 1; `claude auth status` prints `"loggedIn": false` and exits 1. Logged in, both exit 0. The commands that fix it are `codex login` and `claude auth login`.
- **whyline's `init`** already has `--yes`, `--no-instructions`, `--no-hooks` and `[Y/n]` prompts, so `--relay` and `--no-relay` fit its style.
- **`whyline sync` exits 3** with `whyline is not initialised here. Run: whyline init` when whyline is not set up: the signal the preflight needs.

## Decisions

- **The relay stays opt-in.** `whyline init` asks with default No. `--yes` alone does not opt in, because the relay launches agents unattended and spends quota. `--relay` opts in explicitly.
- **Optional extra, not a hard dependency.** `whyline[relay]` adds `whyline-relay>=0.2.1,<0.3`. whyline itself keeps zero required dependencies, and only the `relay` subcommand ever imports the relay, lazily.
- **Both interfaces stay.** `whyline-relay` (standalone install) and `whyline relay` (combined) run the same code.
- **Adding and removing later** is `whyline relay init` and `whyline relay remove`, plus `whyline init --relay`.

## Step 1: whyline-relay 0.2.1 (run through the relay, in `~/relay-test/relay-021`)

The requirements are the plan in that clone's `plan.md` (RELAY-23 to 25):

- **RELAY-23 `plan-format`:** prints the plan rules and a paste-ready prompt for an AI drafting a plan; `--prompt` prints only the prompt; a test proves the example inside it parses with the real parser.
- **RELAY-24 `doctor` and preflight:** eight checks (git repo, whyline initialised, relay set up, agent programs on PATH, logins, plan valid, clean tree, no live run); `start` and `resume` refuse before launching anything; `--skip-checks`; `--dry-run` runs none of it; external commands go through an injectable runner so tests never launch a real agent.
- **RELAY-25 embeddable:** `main(argv=None, prog="whyline-relay")`; every hint uses `prog`; a guard test forbids a hard-coded command name creeping back into `src/`.

Verification: my acceptance tests (`test_accept_021.py`, 28 tests, run with `codex` and `claude` stand-ins on PATH that can be logged in or out) written before the run; they fail on the released code and are run against the result. Then the usual: suite, tripwires, cherry-pick into the real repo, release notes, pre-flight, tag, verify from PyPI.

## Step 2: whyline 0.3.0 (run through the relay in a fresh clone of the whyline repository)

- **WL-1, `whyline relay <args>`:** run `whyline_relay.cli.main(args, prog="whyline relay")` in-process, importing it lazily; a friendly message and exit 1 with the install commands if it is not installed; `relay = ["whyline-relay>=0.2.1,<0.3"]` optional dependency; no other command may import the relay; README section "Automated mode (optional)".
- **WL-2, `whyline init` offers the relay:** `--relay` and `--no-relay`; interactive question `... [y/N]` defaulting to No; `--yes` alone does not opt in; no terminal is No; skipped with a message if already set up; runs the relay's own `init` in-process (its confirmation and permissions listing stay); relay missing means an install hint and exit 0, unless `--relay` was explicit (exit 1); next-steps text; `whyline init` without the relay behaves exactly as before.

Exact requirement text for both is kept with the run's plan when it is created.

Verification for real, after publishing 0.3.0: `uv tool install 'whyline[relay]'` into a temporary tool directory, then `whyline relay --help`, `whyline init --relay` in a scratch repository, `whyline relay doctor`, `whyline relay status`, and `whyline relay remove`. Also confirm that a plain `uv tool install whyline` still works and `whyline relay` gives the friendly message.

## Risks and open questions

- The whyline repository is a published product with users. Its `init` change must not alter default behaviour: covered by "behaves exactly as before" tests, and an independent check that `whyline init --yes` output is unchanged.
- `uv tool install 'whyline[relay]'` with an *extra* is assumed to behave like `--with` (the dependency is importable). The `--with` case is measured; the extra is verified only after WL-1 exists, so the plan says to test it for real before publishing.
- The relay's preflight runs `codex login status` and `claude auth status`. If either tool changes those commands, the check degrades to a `warn`, by design.
- 0.2.1 makes the relay's `main` a public embedding API; renaming it later is a breaking change.
