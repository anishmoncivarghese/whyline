# whyline 0.3.5

Typing `whyline` with no arguments now starts an interactive chat REPL (`whyline-relay chat`, if whyline-relay is installed) — the terminal orchestrator this project's N-roles design has been building toward.

## What's new

- **Bare `whyline` execs into `whyline-relay chat`** via a new `cli.exec_into_chat(which=None, exec_fn=None)`, using the same `which`/`exec_fn`-resolved-at-call-time pattern `runner.py` already established (and already tests via monkeypatching, to avoid the exact "hung a test run" defect this project has been bitten by twice before). If whyline-relay isn't installed, `whyline` falls through to its normal usage output, unchanged.
- See whyline-relay's own 0.2.16 release for what the chat REPL itself does — this piece is purely the thin, zero-logic-duplicated delegation.

## How it was checked

- 325 tests (324 before).
- Built with Grok as implementer and Codex as reviewer via whyline-relay. Grok's own work was correct both times it ran, but it got cancelled before calling `whyline handoff` on every single turn — this project's `pytest -q` doesn't print the usual "N passed in Ys" summary line, and Grok's own habit of re-checking for that line before finishing caused it to stall and get cut off. The orchestrator (Claude) independently verified each turn's diff and the full suite before committing and handing off on Grok's behalf each time.
- Grok itself independently found a real gap in the implementation plan: an existing test (`test_no_command_is_a_usage_error`) called `cli.main([])` completely unmocked, which — once this feature was wired in — would have actually exec'd into a real, installed `whyline-relay` and replaced the test process itself. The plan document was corrected and the test was fixed to mock the new delegation before merging.

## Known issues

Bare `whyline` isn't independently useful without whyline-relay 0.2.16 installed alongside it (it delegates entirely to `whyline-relay chat`). Both are released together for exactly this reason.
