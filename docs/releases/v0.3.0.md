# whyline 0.3.0

**Optional automation. Nothing changes unless you ask for it.** whyline still has no required dependencies, and every command behaves as in 0.2.2 unless you opt in to the automated relay.

## What's new

- **`whyline relay <command>`** runs the separate [whyline-relay](https://github.com/anishmoncivarghese/whyline-relay) program from inside whyline, so one install gives you both: `uv tool install 'whyline[relay]'`. It passes every argument and the exit code straight through (`whyline relay --help` shows the relay's own help), and the relay's hints say `whyline relay ...` rather than `whyline-relay ...`. If the relay is not installed it prints how to install it and exits 1. Nothing but the `relay` subcommand ever imports it.
- **`whyline init` can set the relay up.** New options `--relay` (`Also set up the automated relay.`) and `--no-relay` (`Do not offer the automated relay.`), mutually exclusive. Interactively `init` asks `Also set up the automated relay (Codex implements, Claude reviews and commits, unattended)? [y/N]`. The default is **No**, and having no terminal also means No. `--yes` accepts whyline's own prompts and does **not** opt in to the relay, because the relay launches agents unattended and spends quota. If `.whyline/relay/config.toml` already exists the question is skipped. If the relay is missing, `init` prints the install hint and still succeeds, unless you passed `--relay` explicitly (exit 1); whyline's own setup is done and stays either way.
- **An optional dependency group** `relay = ["whyline-relay>=0.2.1,<0.3"]`.
- README: an "Automated mode (optional)" section.

## Things to know

- **Installed as `whyline[relay]`, there is no `whyline-relay` command on your PATH.** A package's dependencies do not get their commands exposed, only the package you named. Use `whyline relay <command>`. To have both, also run `uv tool install whyline-relay`.
- **Interactive `init` has one more question.** Scripts that pass `--yes` or the `--no-*` flags are unaffected, and so are scripts with no terminal (the answer is No). A script that feeds answers on stdin should add `--no-relay`.

## Upgrading

`uv tool upgrade whyline`. Nothing needs to change in your repositories. To add the automation later: `uv tool install 'whyline[relay]'`, then `whyline init --relay`, or `whyline relay init` in a repository that is already set up. `whyline relay remove` takes it out again.

## How it was checked

- 260 tests (237 before). The two tasks behind this release were each implemented by Codex, then reviewed and committed by Claude, by running whyline-relay on its own plan: one round each.
- 30 independent acceptance tests written from the requirements before the run. They include a byte-for-byte comparison of `whyline init`'s output and written files against 0.2.2 for `--yes`, `--no-relay`, `--no-instructions` and `--no-hooks`, and four tests against the real relay.
- For real, from the built wheel: `whyline[relay]` installs whyline and relay 0.2.1 from PyPI, `whyline init --relay`, `whyline relay status` and `whyline relay remove` work, and a plain install prints the friendly message.

## Known issues

- The `relay` extra pins `whyline-relay<0.3`. A later relay 0.3 will need the pin widened in a whyline patch release.
- Tested on macOS. The automation has not been run on Windows.
