# whyline 0.3.19

Fixes from using 0.3.18's Brainstorm for real.

## What's fixed

- **Enter in the brainstorm form no longer crashes the console.** Pressing
  Enter in the topic box sent the event on to the console behind the form,
  which looked for its own message box on the form's screen and crashed.
  Enter now starts the brainstorm, the same as clicking Start.
- **The console no longer crashes if anything updates while a dialog is
  open.** It had the same underlying flaw: brainstorm progress lines or the
  spinner could crash it whenever a dialog was on top. Every lookup now
  goes to the console's own screen.
- **A focused model checkbox is readable.** It looked like an empty text box,
  because Textual's focus border covered the one-line label; it's now a
  highlighted row.
- **Sending while something is running no longer throws its result away.**
  Sending a chat message during a brainstorm silently discarded the whole
  brainstorm's result. Now you get "Still working on the last request --
  wait for it, or press Stop." and your text stays in the box. Slash
  commands and mode buttons still work meanwhile.
- **No traceback when quitting mid-reply.**

## What's new

- **Per-model brainstorm progress**, from whyline-relay 0.2.23's structured
  progress: lines like `[2/4] Codex succeeded pass-zero (41s)` as each model
  starts, finishes or fails, instead of one "Researching independently"
  line for minutes. whyline now requires whyline-relay 0.2.23 or later
  (which also fixes Antigravity in relay's own `/brainstorm`).

## How it was checked

- Regression tests for each item, including Enter in the topic box and
  rendering while a dialog is open.
- 8 consecutive full-suite runs green (the spinner-at-shutdown flake failed
  about one run in three before).
- Screenshot of the form with a focused checkbox.
