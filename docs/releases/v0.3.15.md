# whyline 0.3.15

Usability fixes for the mouse TUI, from using 0.3.14 day to day: there was
no click path back to chat once in relay, the prompt box gave no hint it
was for typing, and /help listed command names without saying what they did.

## What's changed

- **Mode switch**: a `Mode: [Command] [Chat] [Relay]` row replaces the
  Route button, which could only ever switch to relay. The active mode is
  highlighted, so you can see where you are and click to anywhere.
- **Prompt**: the input now shows a placeholder for the current mode
  (`whyline command, e.g. status or log`, `Message claude...`, or the relay
  verbs). Enter sends, and Send sits to the right of the input.
- **Transcript**: what you type is echoed as `› text` in cyan, so the
  transcript reads as a conversation.
- **Help**: /help explains the three modes and gives each command a
  one-line description (the keyboard console gets this too).
- **Model**: /model marks the active agent and says how to switch.
- **Route**: choosing the mode you're already in says `Already in X mode.`
  instead of repeating `Mode is now X.`
- **Stop**: greyed out unless a reply is actually running.

## How it was checked

- New headless-pilot tests for the mode switch, placeholder, Enter-to-send
  echo, Send placement, and Stop enablement; shared-handler tests for
  /help, /route and /model.
- Full suite green.
