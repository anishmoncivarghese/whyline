## What it does

Seven commands: `init`, `note`, `explain`, `brief`, `run`, `timeline`, `status`.

Two agents write to one decision record and read from it. The one that finishes
leaves behind what it decided and what it rejected; the one that starts picks it
up. Because the record is committed as plain Markdown, `whyline explain` still
answers why a line exists six months later.

- **Zero production dependencies** — standard library only. Python 3.11+, plus git.
- **Never touches a credential.** `run` replaces itself with the vendor's own CLI
  via `exec`, so each vendor authenticates itself and your existing subscriptions
  just work. No API keys, nothing metered.
- **Local only.** No accounts, no telemetry, no paid tier, ever. Apache-2.0.

## The assumption this was gated on

The design rested on one unproven claim: that agents would actually record their
reasoning when asked. That was measured before the features depending on it were
built — 19 decisions across 14 commits on a real project, Claude Code at 150% of
its non-trivial changes against a 60% gate, Codex at 130% against a separate "at
least one firing" gate. Every one carried a rationale and a concrete rejected
alternative, and Codex was never reminded.

## Notes

Published via PyPI Trusted Publishing (OIDC), so no long-lived token exists to
leak. The release workflow refuses to publish if the tag disagrees with
`pyproject.toml`, or if the sdist contains internal notes or absolute home paths
— a gate added after a build swept 27 files of review workspace and a settings
file containing local shell approvals into the default sdist.

macOS and Linux are verified in CI across Python 3.11 and 3.13. Windows is not.

the project's own decision record. This release shipped without them.*
