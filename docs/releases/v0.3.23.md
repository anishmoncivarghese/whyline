# whyline 0.3.23

Brainstorm roadmap item 4: the local ledger stops keeping your raw prompts
by default, can be pruned, and is read more cheaply.

Measured on this repository: raw prompt text was 81% of a 2.1 MB ledger,
and nothing but `timeline --include-prompts` ever read it. Load time was
fine (16 ms) and grows linearly (about 450 ms at 107 MB), so no index or
database was added; commands that don't need prompts now skip them.

## What's changed

- **Prompts are no longer stored as text by default.** New prompts are
  recorded with their length and a SHA-256 hash only. Choose with
  `whyline ledger policy metadata|redacted|full`:
  - `metadata` (default): no text.
  - `redacted`: text with secret-shaped strings masked (API keys, GitHub
    and Slack tokens, AWS keys, JWTs, emails, long hex, `password=…`).
    Best effort, not a guarantee.
  - `full`: the previous behavior.
  The setting lives in `.whyline/config.json`, which is local and
  gitignored (whyline adds it to `.whyline/.gitignore` for you).
- **`whyline ledger scrub-prompts [--dry-run]`** applies the current policy
  to prompts already recorded. Existing prompt text is left alone until you
  run it.
- **`whyline ledger prune --older-than DAYS [--dry-run]`** removes old
  prompt, file-touch and session events. Decisions, handoffs, closes,
  attachments and retractions are never removed.
- **`whyline ledger stats`**: size, events per type, prompt bytes, policy.
- **Lighter reads.** `brief`, `sync`, `decisions`, `attach` and `retract`
  skip prompt and file-touch events without decoding them (about 3x faster
  on a large ledger). `status`, `explain` and `timeline` still read
  everything.
- `timeline --json --include-prompts` says "[not captured:
  prompt_capture=metadata]" for prompts that were never stored.
- Appending to the ledger now takes its lock (about 0.1 ms per event), so a
  hook firing during a prune or scrub waits instead of being lost.

## How it was checked

- 20 new tests in `tests/test_ledger_policy.py`: capture under each policy,
  masking, config and gitignore, prune (cut-off, kept types, dry run),
  scrub, stats, a hook firing mid-rewrite (locked and unlocked writers),
  the light read path matching a full read, and timeline wording.
- On this repository: `stats`, and dry runs of prune and scrub (1,682 and
  919 events). No data was changed.
