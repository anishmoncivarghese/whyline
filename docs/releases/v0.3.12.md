# whyline 0.3.12

Windows compatibility fixes (sub-project #5 of the unified console
roadmap, "cross-platform packaging & release readiness"): CI added
`windows-latest` for the first time this same cycle, found five real
failures on its very first run, and every one is now fixed and verified
green on actual Windows CI, not assumed.

## What's fixed

- `whyline claim`/`release`'s concurrent-safe file locking no longer
  depends on `fcntl` (a POSIX-only module that doesn't exist on Windows at
  all). Replaced with a portable lock using exclusive file creation
  (`os.open` with `O_CREAT | O_EXCL`), honored identically on every
  platform, with stale-lock detection for a crashed process.
- 71 test fixtures across the suite now specify `encoding="utf-8"`
  explicitly. Windows defaults text I/O to the system locale's own
  encoding, not UTF-8 -- this project's own prose (em-dashes throughout)
  was silently mis-encoded and then failing strict UTF-8 reads back.
- Codex's `apply_patch` hook now records touched file paths with forward
  slashes on every platform, not the OS-native separator.
- The `whyline note` failure-path test now simulates an unwritable target
  by making its path a directory -- portable everywhere -- instead of a
  POSIX-only `chmod` trick that never restricted Windows writes at all.

## How it was checked

- The actual `windows-latest` CI job, for both Python 3.11 and 3.13 --
  not just macOS/Linux locally. Every job (including the new
  `test-with-extras` job covering `console`/`relay`/`ui`) is green on
  `main` for the first time.
- All four fixes were implemented by Antigravity and reviewed and
  approved by Codex.
