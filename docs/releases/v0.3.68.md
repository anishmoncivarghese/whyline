# whyline 0.3.68

Fixes for the Release button's security check: it no longer reports ordinary names and sentences as leaked API keys, an **Allow** now lasts across versions, and **Copy report** really copies. Needs whyline-relay 0.2.42 or later, the same as 0.3.67.

## What's changed

- **Far fewer false "Generic API Key" findings.** gitleaks' generic-api-key rule captures the value after a word like `key` or `secret`, and gitleaks judges how random that value is. whyline judged the whole match instead, so lines such as `ALLOW_KEY = "telegram_allow"`, `if key == "salary_min":` and the sentence "checks a release for leaked secrets, vulnerable dependencies" were reported as keys, and the Security check blocked the release. whyline now takes the secret the way gitleaks does: the group the rule names, else the first part of the match that was captured. In whyline's own repository this cut the secret findings from 27 to 1, a deliberately key-like value in a test. Real keys are still found.
- **An Allow lasts across versions.** Files inside a source distribution sit under a `<name>-<version>/` folder. That folder was part of each finding's fingerprint, so an **Allow…** stopped matching at the next version. Packaged files are now fingerprinted by their path inside the project, which also matches the same file in your working tree, so one Allow covers both.
- **Copy report and the other Copy buttons copy.** They used the terminal's clipboard escape code (OSC 52), which macOS Terminal ignores, so they said "Copied" while nothing arrived. Every Copy in the console now uses `pbcopy` (or `wl-copy`, `xclip`, `xsel`, `clip`) first, and the escape code only when none of those is available.

## Upgrading

```bash
uv tool upgrade whyline --upgrade-package whyline-relay
```

Then restart `whyline console`.
