0.1.0 shipped with only half its instruction, and no way to ever fix that in a
repository that had already run `init`. Both are fixed here.

## The read instruction was missing

`whyline init` writes an instruction into `AGENTS.md` asking agents to record
their reasoning. It never asked them to *read* it. So the record accumulated and
nothing consulted it — half the product had no instruction behind it, which is
the half that makes handoff work at all.

The block now leads with the read directive:

```
At the start of a session, before touching code, run:

    whyline brief
```

The wording is not arbitrary. A *declarative* instruction was observed being
ignored unprompted through a six-hour session, while an *imperative* one with a
trigger, an exact command and pre-authorisation fired twice without a reminder.
The read directive carries all four parts that observation identifies: when, the
exact command, pre-authorisation, and a verification the agent can act on.

## `init` could not upgrade an existing block

0.1.0 returned `already-present` for any existing block, so an improved
instruction could never reach a repository that had already been initialised —
including this project's own. Re-running `whyline init` now upgrades an outdated
block in place and leaves everything you wrote around it untouched.

This is why the fix above can actually reach you: without it, 0.1.1's better
instruction would only have helped people initialising for the first time.

## Also

- A test asserting the instruction must *not* mention `whyline brief` was removed.
  It was correct when written — `brief` was gated on a pending experiment — but it
  outlived its reason and then actively blocked the fix above. It now checks the
  real invariant: every command the instruction names is one the CLI provides.

*These notes were written retroactively, in 0.1.3, from the commit history and
the project's own decision record. This release shipped without them.*
