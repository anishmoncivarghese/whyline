# whyline 0.3.9

Two bug fixes affecting anyone who upgraded to account-capability gating
(0.3.7/0.3.8) with an account.json written before it existed.

## What's fixed

- **Account detection now self-heals a pre-0.3.7 `account.json`.** A file
  saved before account-capability gating shipped has no `available` key at
  all and no `antigravity`/`grok` entries -- it was being trusted as
  "already detected" forever, permanently marking every agent unavailable
  with no way to recover short of manually running `whyline account
  detect`. `ensure_detected()` now recognizes this old schema and
  re-detects automatically.
- **The entry menu no longer execs into chat after a failed model setup.**
  Choosing "set a model first" and having it fail (e.g. no agents
  detected) used to silently proceed into `whyline-relay chat` anyway, with
  no indication you'd left the shell for an AI conversation. It now stops
  and tells you to fix the issue and run `whyline` again.

## How it was checked

- Full suite passes (365 tests).
- Reproduced both bugs against this machine's own real, stale
  `~/.whyline/account.json` (dated 2026-09-25) before fixing them.
