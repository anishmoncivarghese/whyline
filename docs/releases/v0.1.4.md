**A documentation release. No behaviour changes, no API changes.** If you are
running 0.1.3, nothing about how the tool works differs here.

## Why it exists

0.1.3's README said whyline's read-side instruction fired in 67% of sessions.
The measured figure is **50%**, and 50% happens to sit exactly on the threshold
that was fixed before collection — the band immediately below it is
"unreliable". So the published claim overstated a measured result, and it
overstated it in the direction that flatters the tool.

A README is baked into the published artifact and PyPI does not permit
re-uploading a version, so 0.1.3 could not be amended in place. This release
exists to get the corrected figure onto the package page.

Spending a version number on a prose fix is a real cost, and the first decision
was to let the correction ride along with the next substantive release instead.
That was reversed: leaving a known overstatement on the front page of a project
whose entire argument is *record what actually happened* was the wrong trade,
however small the sentence.

## What the corrected claim says

- Claude Code ran `whyline brief` unprompted at the start of **2 of 4** sessions
  it owned — 50%, meeting a 50% threshold with no margin.
- Each session is worth 25 percentage points at this sample size, so the figure
  is directional. The trend across rounds has been **downward**, not up.
- Codex was separately observed reading unprompted, and has no denominator,
  because `SessionStarted` events are written by the Claude Code hook alone.

The earlier 67% was a 3-session figure. A 75% reading also appeared briefly and
was an artifact of the analyser crediting a Codex read to a Claude session; that
bug is fixed, and the superseded figures are kept in `m0/READ-SIDE-PROTOCOL.md`
so the trend stays legible rather than being silently restated.

## Also in this release

Nothing that ships. For completeness, `main` also gained retroactive release
notes for 0.1.0 through 0.1.2, the analyser fix above, and the corrected
read-side write-up — all under `docs/` and `m0/`, which the publish gate
deliberately excludes from the distribution.
