# whyline 0.3.69

Plans now come with a written trail. A new **Docs** flow drafts, reviews and approves a product PRD, a plan and a test plan before any code is built, then ties the finished build back to those documents. A new **Project home** step helps you start a project in the right folder. Needs whyline-relay 0.2.41 or later.

## What's changed

- **A document set for every run (SDLC-1..29).** A run can start with a versioned set of documents sized to the work: PRD, plan, test plan, build inputs and decisions. Each document keeps its history, a review log and an approval, and is marked out of date when a document it depends on changes. Documents can be drafted, revised or discarded in the console, or imported from a file (including PDF and DOCX). Stages run automatically or with a human approving each one, and you can switch between the two mid-run. In Auto docs runs there is a **Pause after this stage** option, and Human mode is remembered.
- **A Docs screen in the console.** The New plan form lets you choose the start, size, PRD, mode, build and roles. The Docs tab shows the live Stages line, the active plan's document set, earlier plans, version history with a picker, review actions with feedback forms, and an export pack. All of it is read from the same documents the CLI uses. `whyline docs` has 11 subcommands that match.
- **One product PRD (PRD-1..2).** Instead of a PRD per feature, whyline keeps a single versioned product PRD. Feature and Large runs update only the sections they change and publish the next version (v1.1, v1.2, v2.0 for a major change), or record "No PRD change". The PRD update pane shows changed sections, a unified diff and the whole document.
- **Fresh-eyes review (GFR-1..6).** Each document is reviewed by separate, read-only reviewers that never resume an earlier session. Findings are ranked Blocker, Major or Nit. In Auto mode the review is a gate: pass, fix (up to two rounds) or stop. A Findings panel and `whyline review` / `whyline findings` commands show them. The build record gains a check for drift from the existing codebase.
- **Traceability (TRC-1..2).** Plans and test plans declare which requirements they cover. whyline reports coverage and the build record includes a requirements table that says whether each one was met, worked out from the checkout.
- **Docs on the default branch (WTD-1).** Documents live in their own checkout of the default branch and are committed there by path. whyline never pushes them.
- **Changing the plan while building, and closing out (LIFE-1..3).** If the plan changes during the build, whyline detects it, versions the amended plan and records it in the build record. **Close** archives the document set and can open a pull request if you ask for one. It is available in the console and the CLI.
- **Project home (HOME-1..6).** After a brainstorm, a new project can go in a new folder (whyline suggests 2-3 names and you choose the parent folder) or in this repository. whyline creates the folder, runs `git init`, adds a README and the first commits, moves the document set across and switches the console there. A GitHub repository can be created too. It is private by default and is made only after you confirm. The console has a Project home flow for this, and the CLI has matching commands.
- **Smaller change.** Chat Brainstorm no longer offers the Test planner role. It is still available in Relay Plan.

## Upgrading

```bash
uv tool upgrade whyline --upgrade-package whyline-relay
```

Then restart `whyline console`.
