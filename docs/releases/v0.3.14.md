# whyline 0.3.14

Four real bugs in the mouse TUI (and the account detection it depends on),
found while looking at a screenshot of the console in actual use: the
transcript pane was starved for space, the button row had a dead strip
beneath it, output couldn't be copied out of the app, and the Model button
falsely reported no agents were available. A fifth fix makes the console's
default "command" mode -- type a whyline subcommand directly, no `whyline`
prefix needed -- discoverable instead of silent.

## What's fixed

- **Layout**: `RichLog`, `TextArea`, and the button row's `Horizontal`
  container all default to Textual's `height: 1fr`, so the screen split
  into three equal bands -- the transcript got only a third of it, the
  prompt box got a whole band for what's usually one line of text, and the
  three-row button row sat inside a band as tall as the transcript's,
  leaving empty space beneath the buttons. The transcript now gets the
  rest of the screen after a small fixed-height prompt, and the button row
  hugs its buttons exactly.
- **Copy**: this project pins `textual<1.0`, which predates Textual's
  text-selection feature, so there was no way to select or copy transcript
  text from inside the app. A new Copy button pushes the whole transcript
  to the system clipboard via OSC 52 (`App.copy_to_clipboard`), which
  works over most terminals without needing mouse selection at all.
- **Model detection**: `whyline account detect` correctly finds and caches
  every available agent globally, but `available_agents()` blindly trusted
  a per-repo confirmation file over that global data -- and a repo file
  written before 0.3.7's `available` field (just `plan`/`detected_at`, no
  agent marked available or not) made every agent look permanently
  unavailable, even with fresh, accurate global detection sitting right
  there. A repo file with no `available` key on any agent is now treated
  as pre-schema and skipped in favor of global data.
- **Mode visibility**: the TUI's header now shows `mode: command` (or
  `chat`/`relay`), kept in sync across `/route`, plus a one-time
  onboarding banner on mount. The keyboard console's prompt already showed
  `(mode) >` before every line; the TUI had no equivalent, so typing
  ordinary conversation in the default command mode looked like the
  console had silently broken instead of trying to run it as a `whyline`
  CLI invocation.
- **Friendlier command-mode errors**: when the first word you type in
  command mode isn't a real whyline subcommand, you now get a one-line
  explanation and a pointer to `/help` or `/route chat`, instead of
  argparse's raw multi-line "invalid choice" usage dump. A real error from
  a valid command's own bad flags still shows its actual message,
  unchanged.

## How it was checked

- New regression tests for each fix (layout geometry via a headless
  Textual pilot, the Copy button's clipboard call, the stale-repo-schema
  fallback, and the friendly unknown-command message).
- Full suite green: 294 tests passed.
