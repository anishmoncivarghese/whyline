# Whyline 0.2.0

Whyline 0.2.0 adds an explicit, compact active-task relay for two-terminal
Claude Code and Codex workflows. It remains a context tool, not an orchestrator.

## Active handoffs and sync

- `whyline handoff` records task id, from/to agent, status, summary, changed
  files, tests/results, risks/questions, and base/current commit.
- `whyline sync` combines that handoff with current Git state, advisory
  ownership, and task/file-relevant decisions in a nonce-fenced packet.
- `whyline run` now injects the sync packet and accepts `--task-id`, repeatable
  `--file`, and `--token-budget` options.
- Active handoff and ownership files are atomically replaced, gitignored, and
  local to the checkout. Durable decisions remain committed Markdown.

## Smaller, attributed history

- `brief` defaults to a 1,200-token approximate budget and can filter by task or
  file. The former ten-decision default measured 10.8 KB; the same repository is
  about 3.3 KB after this change.
- Decisions can record `--actor`, `--role`, and `--task`; those fields survive
  the committed Markdown round trip.
- `brief`, `explain`, and `status` now share one ledger-plus-committed history
  loader, so fresh clones see durable decisions consistently.
- Committed day-precision dates can support medium-confidence attribution, but
  never a high-confidence timestamp-window claim.

## Safer parallel work

- `whyline claim` and `whyline release` maintain advisory task/file ownership.
- Overlap between different actors produces warnings but never blocks work.

## Codex capture and honest health

- `init` now merges project-local Codex hooks alongside Claude Code hooks.
- The Codex hook records stable lifecycle fields and explicit `apply_patch`
  paths. It deliberately does not infer file effects from arbitrary shell text.
- Codex project hooks require review through `/hooks` before they run.
- `status` reports configuration, executable discovery, last observed event and
  age separately for Claude and Codex. Configured-but-unobserved is no longer
  presented as live recording.

## Evidence correction

The read-side experiment is closed at 3 qualifying Claude reads across 7
sessions: **43%**, below the precommitted 50% threshold. Automatic instruction
reading is therefore documented as unreliable. `run` is the supported reliable
handoff path; direct-session `sync` remains a useful best-effort fallback. Codex
produced nine observed reads, but no session denominator, so that is not a rate.

No tag was created and nothing was published as part of this implementation.
