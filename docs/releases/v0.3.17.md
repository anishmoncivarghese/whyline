# whyline 0.3.17

The console now tells you which agents you can use, why the others aren't
available, and how to fix them, and it notices when that changes.

## What's changed

- **`/model` lists all four agents**, not just the available ones, with
  whether each is ready, its plan (or "API key"), its configured model,
  which is active, and a fix for any that aren't available:

  ```
  claude       ✓ pro                           model: opus  (active)
  codex        ✗ not logged in                 -> Run /login codex
  antigravity  ✓ installed (login not checked) model: default
  grok         ✗ not installed                 -> Install grok, then /model refresh
  ```

- **Re-checks instead of refusing.** Detection used to run once, ever. Now
  `/model <agent>` on an unavailable agent re-checks first, so one you've
  just installed or logged into works straight away. If it's still not
  available you get the reason and the fix, not just "not available here".
- **`/model refresh`** re-checks every agent on demand.
- **`/login <agent>`** runs the agent's own login in your terminal
  (`claude auth login`, `codex login`, `grok login`), with the full-screen
  console stepping aside while it runs, then re-checks. whyline never sees
  or stores credentials. Antigravity has no separate login command, so
  `/login antigravity` explains how to sign in via `agy`.
- **Unknown agent names are caught** (`/model cluade` -> "Unknown agent").
- **Model suggestions after picking an agent**: claude's own aliases
  (`fable`, `opus`, `sonnet`); for antigravity, `agy models` lists them;
  codex and grok take any model ID your account accepts. Names are still
  never validated against a list, so new models work the day they ship.

## Honest limits

Only claude and codex have a non-interactive login check. For antigravity
and grok, "available" means installed; they're labelled "login not checked"
rather than claimed as logged in.

## How it was checked

- New tests for status labels (plan, API key, not installed, not logged in,
  turned off), re-check-before-refusing, `/model refresh`, typo handling,
  `/login` validation, the keyboard console's login flow, and the
  full-screen console suspending around the login.
- Console tests now isolate detection from the developer's real home
  directory and never run the real `claude auth status`.
- Ran `/model refresh`, `/model <agent>`, `/login antigravity` and a typo
  against real detection on a machine with all four agents installed.
