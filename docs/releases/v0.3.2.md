# whyline 0.3.2

`whyline account detect` checks which plan/tier `codex` and `claude` are actually authenticated under — not just whether they're logged in — and `whyline model` lets you pick a model per agent per repo, with `whyline run` using it automatically. This closes the N-roles design's last deferred piece, "subscription-aware setup."

## What's new

- **`whyline account detect`** reads Claude's own `auth status` (`subscriptionType` field, directly) and decodes Codex's local auth token (`chatgpt_plan_type` claim) to report the real plan/tier each is authenticated under — Claude Pro/Max/Team, ChatGPT Plus/Pro/Team. Runs once per machine, cached in `~/.whyline/account.json` (whyline's first-ever global, cross-repo file); `whyline account status` confirms it once per repo (`.whyline/account.json`, gitignored — this is personal plan/billing info, never committed).
- **`whyline model`** picks a model per agent (`codex`/`claude`/`antigravity`) for the current repo, showing the detected plan as informational context. `whyline model set <agent> <model>` sets one non-interactively; `whyline model status` shows current choices. No value is validated against a list of real model names — a wrong choice just fails at the agent's own invocation time, same as today.
- **`whyline run` uses the selected model automatically** — no flag needed. `runner.build_argv`/`launch` gain an explicit `model` parameter (never resolved internally, keeping both functions pure and testable — `cmd_run` resolves it once, the same way `which`/`exec_fn` are already resolved outside `launch` rather than captured as defaults).
- **Antigravity's model can be set here too**, and `whyline run antigravity` is fully safe with it — that command hands the terminal to a human, unaffected by Antigravity's own headless-mode limitations. `whyline model` prints a caveat when you set Antigravity's model, since those limitations *do* apply if you separately configure Antigravity as a whyline-relay role.

## How it was checked

- 318 tests (263 before).
- Every task was independently rebuilt and diff-verified against a real relay-driven sandbox run before merging — built with Antigravity as implementer and Codex as reviewer, the first real production use of Antigravity in this role: all 6 tasks completed with zero pauses, over 1,000,000 tokens of real, verified usage read directly from the run's own logs.
- `whyline account detect` and `whyline model set/status` were verified against a real, separate repository — real plan detection (`codex: plus`, `claude: pro`), real gitignore behavior confirmed after `git add -A`.
- Corrupt/malformed `account.json`/`model.json`, an API-key-mode login (no subscription tier), and one agent's detection failing without affecting the other are all covered by tests written before the implementation, not after.

## Known issues

Antigravity's own subscription/tier is not detected (no verified mechanism exists for it, unlike Codex/Claude). Its headless-mode permission enforcement remains unreliable for narrow scopes — see whyline-relay's README and [google-antigravity/antigravity-cli#548](https://github.com/google-antigravity/antigravity-cli/issues/548) — which is why `whyline model` calls this out when you set its model, without blocking it.
