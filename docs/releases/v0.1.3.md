Agents that *review* code were recording almost nothing. This release is a
one-line change to the instruction that causes it, and an honest account of why
that change might not be enough.

## The instruction now names reviewers, not only implementers

The trigger read *"After completing any non-trivial change, record the
reasoning."* That describes someone who wrote code. A reviewer reading it
faithfully concludes it is not addressed to them — they completed no change.

Across five tasks on one project, the implementing agent recorded a decision
every time. Not one ruling by the reviewing agent reached `decisions.md`.
Judgements like *"fix this bug now rather than defer it"* and *"accept this
deviation from the plan as spec-compliant"* went into a tracker that was never
committed, so they died on clone. That is exactly the reasoning this tool exists
to keep.

`whyline init` now writes a trigger covering both, plus a short paragraph naming
what reviewers actually decide. Existing repositories pick it up by re-running
`whyline init`, which upgrades the block in place.

## This is a hypothesis, not a measured fix

Unlike the write-side and read-side results in `m0/`, **no threshold was fixed
before this change, and its effect has not been measured.** At least three
explanations fit the observation, and this release addresses one:

1. The trigger never named reviewers. Fixed here.
2. The reviewer never loaded the instruction at all — two of the five tasks were
   reviewed from a session rooted in a *different* repository, so the `AGENTS.md`
   in context was not the reviewed project's. No wording fixes this; a cross-repo
   reviewer has no defined target `.whyline`.
3. A dispatched agent follows its dispatcher's prompt rather than `AGENTS.md` —
   already documented under "Switching agents" in the README.

If the next review round still records nothing, cause 2 or 3 is the real one.

## Upgrading no longer loses text silently

Text inside the `<!-- whyline:begin -->` markers belongs to whyline and is
replaced wholesale. That has always been the contract, but 0.1.3 is the first
release to change the block's *content* since `init` shipped, so it is the first
to actually exercise that path in existing repositories — anything you had added
in there would have vanished without a word.

The replaced block is now copied to `.whyline/AGENTS.md.bak` and the path is
named in the command's output. It goes inside `.whyline/` because whyline manages
`.whyline/.gitignore` and never edits the repository's own; a file beside
`AGENTS.md` would show up untracked in every repo that upgraded.

There is deliberately **no** warning that content "may have been lost". On most
upgrades nothing was, and an alarm that fires when nothing is wrong teaches
people to ignore it.

- Corrected a misattributed threshold in the README and in source comments: M0's
