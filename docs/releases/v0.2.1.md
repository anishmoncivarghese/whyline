**`whyline init` no longer produces a dead install if you press Enter.** If you
installed 0.2.0 or earlier, this is worth upgrading for, and worth re-running
`whyline init` afterwards.

## The bug

The two `init` prompts defaulted to **no**:

```
Install shared instructions in AGENTS.md and CLAUDE.md? [y/N]
Install the Claude Code and Codex hooks for this project? [y/N]
```

So the likeliest possible first run — `whyline init`, Enter, Enter — created
`.whyline/` and nothing else. No instruction block, so no agent ever recorded or
read anything. No hooks, so nothing mechanical was captured either. The tool was
completely inert.

It printed `Initialised` and exited 0, so it looked like it had worked. Then
`whyline status` advised running `whyline init` — the command just run.

A closed stdin was worse: `input()` raises `EOFError` there, which was treated as
"no". `whyline init` in a Makefile, devcontainer or CI step therefore installed
nothing and reported success, in the one context where nobody is watching a
prompt to notice.

This violated the project's own rule — degrade with a warning, never fail
silently — at first run, which is the worst possible place for it.

## The fix

- The prompts default to yes and read `[Y/n]`. **Running `init` is the consent**;
  the prompts exist to allow opting out, not to make declining the default.
- A closed stdin now means yes rather than no, so non-interactive setup works.
- `--no-instructions` and `--no-hooks` skip either part explicitly, without
  prompting. `--yes` still accepts both.
- Answering `n` still declines. That has not changed — it is just no longer what
  happens by accident.

The conservatism was not wrong in spirit: these commands do modify files you own.
But `init` is already an explicit opt-in, and since 0.2.0 any instruction block
it replaces is copied to `.whyline/AGENTS.md.bak`. The safety belongs in the
backup, not in a default that quietly yields a tool that does nothing.

## If you ran 0.2.0's init and pressed Enter

You have a `.whyline/` directory and no instructions or hooks. Re-run:

```bash
whyline init
```

Then confirm with `whyline status`. Hooks read `configured but never observed`
until a real event arrives — that is accurate, not a failure; a new session in
each agent will clear it.

## Also

- The README now documents the prompt defaults and the two skip flags.

No other behaviour changed. No API changes.
