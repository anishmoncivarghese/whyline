# whyline 0.3.65

A **Release** button that publishes a version for you, and built-in **security checks** that run before anything is pushed. This release also fixes Chat answers that stopped early, a "Pausing" status that stayed on, and the spaced-out button bar. Needs whyline-relay 0.2.42, the same as 0.3.64.

## What's changed

### Release button
- **Release in Relay mode** checks the repository is ready, bumps the version, writes release notes, commits, pushes, waits for CI, tags and creates the GitHub release. Everything is in `whyline console`, and `whyline release check | run | status | resume` does the same from a terminal.
- **Pick the next version** (patch, minor, major or custom), press **Check**, then **Start**. Check lists each item with ✓ or ✗ and what to do about a ✗, and Start stays off until every item is ✓.
- **Modes:** **ask** (the default) asks before the push, the tag and the GitHub release, and shows the notes for you to use, edit or stop. **step** asks before every step. **auto** asks nothing.
- **Release notes are drafted for you** from the commits since the last tag, with your agent as a fallback.
- **A stopped release resumes** where it left off, without repeating a tag or an upload.
- **Targets**, ticked in **Release → Set up** and saved in `.whyline/release.toml`:
  - **GitHub** (always on)
  - **PyPI**, with trusted publishing
  - **npm**, with trusted publishing
  - **Docker**, to GHCR or Docker Hub
  - **Homebrew**, updating the formula in your tap
  - **Custom**, your own command plus an optional verify command
  Each target's **Set up…** shows what is missing and offers the fix. A target you leave unticked runs nothing.
- **GitHub setup** in the console: status, browser sign-in, and creating and linking a repository.
- **From a plan.** When a relay reaches a release task, it offers **Run Release**, and the Release screen can open by itself once a plan finishes.
- **`docs/release.md`** has a section per target: what it publishes, the one-time setup, which tokens are involved (none held by whyline), and how to check by hand.

### Security checks
- **Built in, nothing to install.** Release's Ready check gains a Security item. Before anything is pushed, it looks at:
  - **Secrets** in the unpushed commits and `.env`-style files, using the gitleaks rule set
  - **Dependencies** pinned in `uv.lock`, `poetry.lock`, `requirements*.txt`, `package-lock.json`, `pnpm-lock.yaml` and `yarn.lock`, checked against OSV.dev
  - **Package contents**: what the wheel, sdist, npm package or Docker build would really publish
- **Secrets are always masked** (`ab****yz`). The full value is never printed, logged, stored, copied or sent to an agent.
- **Only public package names and versions** go to OSV.dev. The secret and contents checks run on your machine.
- **Each finding offers Fix, Ignore once and Allow…**. Allow needs a reason and saves a fingerprint, not the secret.
- **Settings** in **Release → Set up → Security**: block, warn or off for each check, with high and critical dependency issues blocking by default.
- **More, all optional:**
  - **Scan history** for older commits
  - a **pre-commit hook** for staged secrets
  - gitleaks, betterleaks and osv-scanner, when you have them
  - GitHub secret scanning, push protection and Dependabot status, with a button to turn them on
- **Deep audit**, off by default: your main agent reviews the repository for security issues and writes a report outside the repository. It can use many tokens, so it only runs when you ask.
- **`whyline security`** (`scan`, `allow`, `status`, `audit`) does the same from a terminal, and **`docs/security.md`** explains each check and what leaves your Mac.

### Fixes
- **Chat no longer stops at "I'll read the relay snapshot…".** When grok's read-only mode cuts its turn off, Chat retries once and the working line says so. If the retry is cut off too, you get a clear message naming the refused command instead of half an answer. Chat's history now follows the current relay run, and older entries show their date.
- **"Pausing" shows only while a pause is really pending.** It no longer stays on after a pause and resume made from another screen.
- **The button bar wraps into packed rows.** When the buttons don't fit on one line, they use as few rows as fit, with each column only as wide as its button, instead of a wide 6-column grid.

## Upgrading

```bash
uv tool upgrade whyline --upgrade-package whyline-relay
```

Then restart `whyline console`.
