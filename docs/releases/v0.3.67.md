# whyline 0.3.67

**CI jobs to ignore** in Release → Set up now works with job names, so one job that is known to fail no longer blocks every release. Needs whyline-relay 0.2.42 or later, the same as 0.3.66.

## What's changed

- **Ignore one CI job, not the whole workflow.** Wait for CI used to look only at whole workflow runs. A job name such as `test (windows-latest, 3.13)` in **CI jobs to ignore** never matched, and the only way past a failing job was to ignore its entire workflow, which also ignored every other job in it. Now:
  - A job named in the box is left out. A workflow run that failed only because of ignored jobs counts as passed.
  - Wait for CI does not wait for an ignored job that is still running.
  - A failed job that is not ignored stops the release and is named, as `CI failed: ci / test (ubuntu-latest, 3.13)`, with a link to that job.
  - A workflow name in the box still ignores that whole workflow, as before.
  - With nothing in the box, nothing changes and no extra GitHub requests are made.
- **Set up and `docs/release.md` explain both kinds of name.** The field's label gives an example, and the docs' troubleshooting entry says which part of a failure message to copy into the box.
- **A flaky console test is fixed.** `test_see_files` sometimes failed on CI because the Files pane's background follow overwrote the file the test had just shown. The test now stops the follow first.

## Upgrading

```bash
uv tool upgrade whyline --upgrade-package whyline-relay
```

Then restart `whyline console`.
