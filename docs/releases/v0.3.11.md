# whyline 0.3.11

The mouse-enabled TUI (sub-project #4 of the unified console roadmap):
`whyline console --ui` launches a full-screen, clickable console alongside
the existing keyboard-only one.

## What's new

- `whyline console --ui` (requires `pip install 'whyline[ui]'`) -- a
  full-screen Textual app: header, scrollable transcript, multiline prompt,
  and a Send/Model/Route/History/Stop/Help button row.
- Every button dispatches the exact same command the keyboard console
  already accepts (`/model`, `/route`, `/history`, `/help`) through one
  shared `dispatch()` function -- no separate mouse-only logic to keep in
  sync.
- Relay/chat calls run in a background thread so the screen stays
  responsive during a long-running turn or relay call.
- `/stop` cancels the active call for the first time (it was a documented
  no-op in the keyboard console, where nothing could ever be "in flight").
  It's a request, not a guarantee -- Python can't forcibly interrupt code
  already running in a thread, but a cancelled call's result is discarded
  rather than rendered late.
- Bare `whyline console` is unchanged -- still launches today's
  keyboard-only REPL.

## How it was checked

- Full suite passed on the completed plan (MTU-1 through MTU-5).
- Antigravity implemented every task; Codex reviewed and approved all
  five.
- A real layout bug was found and fixed mid-plan: Textual's default
  Button width made the six-button row overflow an 80-column terminal,
  putting Stop and Help genuinely off-screen -- confirmed by directly
  measuring widget regions, not guessed.
