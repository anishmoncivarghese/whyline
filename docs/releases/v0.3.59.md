# whyline 0.3.59

Workflows, part 1: build a workflow of steps in `whyline console`, run it by
hand or on a schedule, and see each run step by step. Also: CV import accepts
a path copied from Finder, and the relay no longer stops when the console is
checking git at the moment it commits.

## What's changed

- **Workflows mode.** A new **Workflows** button in the console opens the
  Library: your repo and personal workflows, each with Run now, Pause/Resume,
  Review & accept, Edit and a daily limit on agent steps. **New** creates one.
  `whyline workflow …` does the same from scripts.
- **Steps.** `set`, `condition`, `switch`, `wait`, `stop`, `approval`, `agent`
  and `deliver` (email or Telegram, only to chats you allowed). Steps read
  earlier results with `{{ steps.<id>.… }}` templates.
- **Builder.** Add, move and delete steps, edit each step's fields, and route a
  condition or switch to a later step. Saving is refused until the workflow
  validates, and a changed workflow must be accepted again before it runs.
  **Dry run** walks the workflow without running agents or sending anything.
- **Triggers.** Run by hand, daily or on weekdays at a time, every N hours, or when files
  appear in a folder. If the Mac sleeps through several due times, the
  workflow runs once to catch up and records the rest as missed.
- **Runs.** The Runs screen shows each run step by step, with Cancel, Retry,
  Approve and Deny. A run interrupted while sending is marked
  `unknown_outcome` and never sends twice: Mark done, Mark failed or Retry
  step settles it (`whyline workflow resolve` from scripts).
- **CV import accepts pasted paths.** A path from Finder's Copy as Pathname
  (wrapped in quotes), a path with backslash-escaped spaces, or a `file://`
  link now imports. Before, `'…/Resume Sep 2026.docx'` was refused as an
  unsupported format.
- **The relay no longer trips over the console's git checks.** The console
  checks `git status` several times a second, and each check could briefly
  lock the repository's index. If the relay committed at that moment, its
  commit failed. whyline now runs git with optional locks off, so these
  checks never take the lock.

## Upgrading

```bash
uv tool upgrade whyline
```

Then restart `whyline console` and choose **Workflows**.
