# whyline 0.3.3

`whyline run grok "<task>"` and `whyline model set grok <model>` now work, the same interactive-hand-to-a-human shape `claude`/`codex`/`antigravity` already have.

## What's new

- **`run` supports Grok (`grok`, "Grok Build")** in addition to Claude Code, Codex, and Antigravity (`agy`). A bare `grok "<task>\n\n<context>"` already starts an interactive session with the prompt — no special flag needed, unlike Antigravity's `-i`.
- **`whyline model set grok <model>`** works too — `MODEL_FLAG["grok"] = "--model"`, following the same pattern as the other three agents.
- No `cli.py` changes were needed: both `whyline run` and `whyline model set` already derive their `choices=` dynamically from `runner.AGENTS`.

## How it was checked

- 322 tests (318 before).
- Built with Antigravity as implementer and Codex as reviewer — zero pauses across both tasks.
- Cherry-picked tree diff-verified byte-for-byte against the sandbox before merging.
- Extended the existing bypass-flag and real-execvp-poisoning tests to cover `grok` alongside the other three agents, including a new forbidden-substring check for Grok's own bypass form, `--permission-mode bypassPermissions`.

## Known issues

whyline itself only ever hands Grok the terminal interactively (like Codex/Claude/Antigravity) — it never runs Grok headlessly or manages its permissions. For unattended use (e.g. as a whyline-relay agent), see whyline-relay's own README section, "Using Grok today, via the generic adapter," which documents real, empirically verified gaps: no non-interactive login-status check, and denial detail limited to a generic `stopReason: "cancelled"`.
