# whyline 0.3.70

Plans now come with a written trail. A **Docs** flow drafts, reviews and approves a product PRD, a plan and a test plan, then records the build against those documents. A **Project home** step starts a new project in the right folder. The README has an SDLC overview, and `docs/sdlc.md` is the full guide. Needs whyline-relay 0.2.41 or later.

## What's changed

- **A document set for every plan.** A run can start with a sized set of documents: five packaged templates, including the PRD, plan, test plan, build inputs and decisions. Each document keeps versioned history, a review log and ordered approvals, and is marked out of date when an upstream hash or version changes. You can draft, revise or discard text in the console, or import a file (PDF and DOCX included). Stages run automatically or with a human at each stop, and you can switch mode mid-run. **Pause after this stage** shows only on Auto docs runs, and Human mode is remembered.
- **A Docs screen and a matching CLI.** The New plan form chooses start, size, PRD, mode, build and roles. The Docs tab is read-only for the active plan: live Stages line, document set, earlier plans, History with a version picker and review log, review actions with feedback forms, a Findings panel with severity counts, and an export pack of ordered header-free Markdown plus history. `whyline docs` has 11 subcommands that do the same work; `whyline review` and `whyline findings` cover Fresh-eyes reviews.
- **One product PRD.** whyline publishes a versioned product PRD and tracks provenance into later documents. The PRD update pane shows changed sections, a unified diff and the whole document.
- **Fresh-eyes review.** Separate, no-resume reviewers look at each document. Gates can pass, fix or stop. A Findings panel counts severity, and the build record gets a codebase-fit drift review with diff context.
- **Traceability.** Plans and test plans declare which requirements they cover. whyline reports coverage, and the build record includes checkout-derived requirement results.
- **Docs on the default branch.** whyline finds or creates a docs worktree on the default branch, with a single-drafter lock so only one stage writes at a time.
- **Plan changes while building, and close-out.** If the plan is amended during the build, whyline detects it, versions it and records it. **Close** archives the set (with auto-versus-human lifecycle metadata) and can open a pull request. Coverage is part of that close.
- **Project home.** After a brainstorm you name the project and choose a new folder or this repository. whyline refuses a shared home before setup. GitHub repository creation is user-triggered and private by default. The console has a Project home flow with repository switching and continuation; the CLI formats names and handles home selection and defaults.
- **README and SDLC guide.** The README now has an SDLC overview, and `docs/sdlc.md` is a comprehensive guide.
- **Smaller change.** Chat Brainstorm no longer offers the Test planner role. It is still available in Relay Plan.

## Upgrading

```bash
uv tool upgrade whyline --upgrade-package whyline-relay
```

Then restart `whyline console`.
