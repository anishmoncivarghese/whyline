# whyline 0.3.66

Fixes for the Release button from its first real use: Set up now recognises a PyPI workflow that publishes with `uv publish` or `twine upload`, and the Close button no longer disappears below the Set up form. Needs whyline-relay 0.2.42 or later, the same as 0.3.65.

## What's changed

- **PyPI Set up finds more existing workflows.** A tag-triggered workflow that publishes with `uv publish` or `twine upload` now counts as your PyPI workflow, as well as one that uses `pypa/gh-action-pypi-publish`. Before, Set up said "No workflow yet" for these and offered **Add workflow**, which would have written a second `release-pypi.yml` that PyPI refuses (its trusted publisher names your existing file) or that races the first to upload the same version. Set up and Ready now name the workflow you have, and the trusted-publisher details show its file name.
- **Close, Check and Start stay on screen.** On a short window the Set up tab pushed the action row below the Release box, so there was no way to close it except Esc. The tabs now scroll inside the box and the action row stays visible, down to 80×24.
- **whyline's own release workflow works with the Release button.** If the GitHub release already exists when the publish job reaches its last step, as it does when the Release button made it, the workflow attaches the wheel and sdist to it instead of failing with "already exists" after PyPI has the upload. If your own workflow also runs `gh release create` on tags, make the same change: check `gh release view "$TAG"` first and use `gh release upload "$TAG" <files> --clobber` when it exists.

## Upgrading

```bash
uv tool upgrade whyline --upgrade-package whyline-relay
```

Then restart `whyline console`.
