# whyline 0.3.39

The backup chain is on the console bar, in order, for every repository.

## What's changed

- **Backup on the context bar.** Next to Agent, a Backup control shows this
  repository's fallback chain: Automatic (resolved from the agents you have
  installed and logged in), None, or a specific agent first. Manage chain…
  opens an ordered editor. The chain is shared by chat, brainstorm, and the
  relay, and Save writes only `config.toml`, as one commit naming the chain.
- **An ordered chain editor.** Tick agents in the order you want them tried and
  move them with Up and Down. Automatic fills an empty list, None clears it,
  and a configured name the console doesn't know stays visible rather than
  being dropped. Set up uses the same editor, and its guided summary reads
  `Backup: codex → grok`.
- **A sticky failover is visible and easy to undo.** When chat has fallen back
  to another agent, the bar shows `using {agent}`. Reset failover (on the bar,
  in the editor, or `/reset-backup`) goes back to your primary without
  touching the chain. `/backups` prints the current chain and any override.
- **Busy-safe.** The chain and the failover can't change while a reply,
  plan, or relay run is in progress; the console tells you to finish or stop
  it first.
- **Narrow terminals.** Below 100 columns the bar's labels shorten. Below 80
  columns Backup moves into the Agent dropdown (`Backup…`) and Save stays on
  the row.
- **Relay mode accepts the relay's own resume command.** Typing
  `whyline relay resume` or `whyline-relay resume` in Relay mode now runs it
  instead of reporting an unknown command, and the pause card says
  `type resume or press Resume`.

Needs whyline-relay 0.2.34.

## Upgrading

```bash
uv tool upgrade whyline
```
